# FAQ · Архітектура (з розбору)

**UI окремо?** Так — лише команди й читання, не книга.

**Навіщо API, якщо є Postgres?** Postgres зберігає. API — правила, auth, переходи, publish у чергу.

**Worker — частина house?** Так. Але він не приймає кліків: він **сам** ходить назовні / робить фон.

**RabbitMQ шле в чергу, worker слухає?** API **публікує** в RabbitMQ; брокер тримає; worker **consume**.

**Worker на кожну дію чи писати через API?** Команди статусу — **через API в Postgres**. Worker — наслідки після факту (webhook, expire…). Не окремий процес «на кожен click», а consumer(и) по типах подій.
